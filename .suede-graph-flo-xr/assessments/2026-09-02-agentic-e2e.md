## Recommendations, ranked

1. **Fix both SDKs to the async contract.** Handle `202`, follow `pollUrl` until the completion
   signal (`model_version` for music; `status: completed` for video/image), return the asset URL.
   Rewrite fixtures from `index.md`, not from memory.
2. **Ship the v2 ElizaOS client publicly.** The private Suede-AI-App fork already speaks
   `PAYMENT-SIGNATURE` and v2 payloads; publish it as `@suedeai/plugin-suede` 2.0.
3. **Add `X-Idempotency-Key` to both clients**, one UUID per intended purchase, reused across
   retries. This is the only guard against double charges on timeout.
4. **Publish the two unspecified areas** in this repository: unknown-field behaviour and the
   payment-payload schema. Add a "clients known to conform" table so drift is visible.
5. **Alias `base` → `eip155:8453`** in the Python SDK's `select_requirement`.
6. **Gate the SDKs in CI against a contract fixture generated from the live 402 challenge**, so
   the next server change breaks the client build instead of a paying agent.
7. **Graph Flo XR**: either document Linux as unsupported in the plugin manifest so remote/CI
   sessions fail fast with a clear message, or add a Linux sandbox backend (bubblewrap/nsjail)
   behind the same clamp.
